Centralized Power BI RLS Governance

Scope intentionally limited to RLS version control, validation, deployment, promotion and monitoring. Report development remains completely outside this solution.

Existing Visualization Process

Untouched by this architecture
  • Report authoring process
  • Visual design
  • Semantic-model creation
  • Measures and business logic
  • Publishing process
The visualization team does not need to adopt code-based report development.

Central IT – RLS Control Plane

Only security artifacts are version controlled
  • RLS role TMDL files
  • Project/environment mapping
  • Security dependency contract
  • RLS validation test cases
↓
Pipeline responsibilities
  • Validate target workspace
  • Validate report exists
  • Validate semantic model exists
  • Validate report → semantic model binding
  • Validate required model objects
  • Deploy only RLS role changes
  • Test and detect drift

Target Power BI Assets

Workspace
Must match configured environment.
Report(s)
Existence + binding validation only. Never modified.
Semantic Model
RLS role objects are updated; all other model content remains untouched.

Important: Power BI RLS belongs to the semantic model. A report is not technically required for the role to exist. The report check is a governance rule that prevents deploying security to an orphaned, renamed, or incorrectly mapped project.
